# dsh-token-frugal（Token 节食）

让长会话不再为「整份文件」和「整页网页」反复付费。

为 DeepSeek Harness 提供三个**延迟加载**工具：

| 工具 | 作用 |
|---|---|
| `read_range` | **只读你需要的几行**：按行号窗口读、按符号找出所有出现位置并带上下文、或只列结构大纲。输出有硬上限。 |
| `tool_catalog` | 列出本会话真正能调用的工具（一行一个）。因为工具一旦延迟，模型必须能自己重新发现它们。 |
| `fetch_recall` | 按字符偏移读回任意被瘦身的结果片段。 |

它还会**瘦身过大的工具结果**：一个文档页可能有 17 万字符（约 4.6 万 token），而且之后每一轮都要重新发送。超过阈值时，网页保留有界头部 + 章节摘要，shell 输出保留**头 + 尾**（诊断信息在尾部），其余用 `fetch_recall` 按需取回。

## 为什么

每次工具往返都会把整段对话重新发一遍。为回答「这个函数在哪」而整份读一个 700 行文件，会把约 9,000 token **永久**写进上下文，之后每一轮都要再付一次。

`read_range` 的 `symbol` 模式只用命中行来回答同一个问题。

## 实测

同一个问题，只换读法：

| 文件 | 行数 | 整份读 | `symbol` 模式 | 节省 |
|---|---:|---:|---:|---:|
| `index.js` | 464 | 4,661 tok | 188 tok | **96.0%** |
| `client.js` | 710 | 9,389 tok | 274 tok | **97.1%** |
| `bench/index.js` | 875 | 8,999 tok | 513 tok | **94.3%** |
| **合计** | | **23,049** | **975** | **95.8%** |

过大的工具结果：

| 对象 | 原始 | 瘦身后 | 节省 |
|---|---:|---:|---:|
| 文档页（真实抓取） | 46,582 tok | 583 tok | **98.7%** |
| shell 输出（287 万字符） | 16,842 tok（宿主截断后） | 1,515 tok | **91.0%**，且**尾部不再丢失** |

token 数为对 Harness 计费规则的确定性近似（中文约 1.7 字/token，代码约 3.8 字符/token），用于横向比较，不等于账单。

**节省比例随对象变大而上升。** 小文件省得少，因为每次调用的头部与上下文窗口有固定下限。

## 安装

```bash
dsh plugin install dsh-token-frugal
```

行 id 固定为 `token-diet`（不随包名变化），在你自己的 `cordis.patch.yml` 里覆盖 `config` 即可在升级后保留配置。

## 配置

| 键 | 默认 | 含义 |
|---|---|---|
| `guide` | `true` | 注入「优先用 `read_range`、不要整份读」的系统提示词段落。**这才是让节省真正发生的关键**：没有它，工具虽然存在，模型仍会整份读文件。 |
| `exposeCatalog` | `true` | 是否注册 `tool_catalog`。 |
| `slim` | `true` | 通过 `tools/post-execute` 瘦身过大的工具结果。 |
| `slimWebTools` | `["web_fetch"]` | 网页类结果：正文头部 + 章节摘要。 |
| `slimShellTools` | `["pwsh","bash","wsl","tty_run"]` | shell 类结果：**头 + 尾**，因为诊断信息在尾部。 |
| `maxInlineChars` | `8000` | 超过此字符数才瘦身。 |
| `headChars` | `1500` | 网页模式保留的头部字符数。 |
| `shellHeadLines` / `shellTailLines` | `60` / `60` | shell 模式两侧各保留的行数。 |
| `durableArchive` | `true` | 把瘦身后的原文存到 `~/.dsh/token-diet/archive`，定位符可跨重启。磁盘不可用时回退内存。 |
| `maxArchiveFiles` | `200` | 超过后修剪最旧的存档。 |

### 为什么 shell 保留尾部

失败的命令把原因写在最后：「拒绝访问」、退出摘要、拷贝数量。宿主自带的 `maxOutputBytes`（64000）只保留头部，还可能截断在行中间，结果是模型看到满屏噪音却看不到错误，只能重跑一次。

### 关于引导段落

- 每轮固定开销约 **162 token**（612 字符）。这就是「建议」的代价，所以 `guide` 做成开关。
- **仅当 `read_range` 对当前渲染作用域可见时**才渲染。
- 段落排序值为 `210`，落在插件引导带（`150` ssh、`152` docker、`200` task board）内。

## 诚实的边界

- **它不会压缩其他插件的工具 schema。** 没有服务或事件能把别的插件的 `ToolSchema` 标记为 `deferLoading`，只有本插件自己的工具会被延迟。
- **`symbol` 模式是文本匹配，不是语义匹配。** 搜 `save` 也会命中 `savesSelection`；不确定标识符时先用 `mode: outline`。
- **原版 `read` 未被改动。** 所以**只有模型真的选用 `read_range` 时才有节省**。
- **存档是用户目录下的明文文件**，任何以你身份运行的程序都能读。抓取内容可能敏感，共享机器上请慎用。
- **没有使用 `spillStore`**：其运行时可用性无法确认，硬依赖会导致瘦身整体失效。
